var kindToDir = map[string]string{
    "table": "tables", "view": "views", "materialized_view": "materialized_views",
    "function": "functions", "sequence": "sequences", "trigger": "triggers",
    "type": "types", "domain": "domains", "enum": "enums",

func defYAMLPath(backupDir string, entry resolve.RestoreEntry) string {
    if entry.Kind == "table" {
        if entry.FromTable != "" {
            return filepath.Join(backupDir, entry.Schema, "tables", entry.FromTable, "partitions", entry.Name, "def.yaml")
        }
        return filepath.Join(backupDir, entry.Schema, "tables", entry.Name, "def.yaml")
    }
    dir, ok := kindToDir[entry.Kind]
    if !ok { return "" }
    return filepath.Join(backupDir, entry.Schema, dir, entry.Name+".yaml")
}

    1. Keep `DiffResult` and `ObjectChange` structs from Plan 01 stub.

    2. Implement `compareObjects(a, b map[string]core.ObjectDef) DiffResult`:
       - For each key in b not in a: parse header from object, append to result.Added
       - For each key in a not in b: parse header from object, append to result.Removed
       - For each key in both: call `diffObject(aObj, bObj)` → []string details; if non-empty, append to result.Changed
       - Sort Added and Removed by key for deterministic output
       - Return result

    3. Implement `diffObject(a, b core.ObjectDef) []string`:
       - If both are `core.TableDef` (value type assertion): call `diffTable(&aT, &bT)`
       - If both are `*core.TableDef` (pointer type assertion): call `diffTable(aT, bT)`
       - Otherwise (non-table): call `diffNonTable(a, b)` returning ["本体変更あり"] or ["定義変更あり"] if different

    4. Implement `diffTable(a, b *core.TableDef) []string` covering:
       - Column add/remove/type-change/nullable-change/default-change (see RESEARCH.md diffColumns example)
       - Index add/remove by name set-difference (same name but different Definition = remove+add)
       - Unique constraint add/remove by name
       - Check constraint add/remove by name
       - RLS enabled/disabled change: `fmt.Sprintf("RLS変更    : enabled %v → %v", a.RLS.Enabled, b.RLS.Enabled)`
       - Note: Triggers and policies are independent objects; detect them in compareObjects by matching TriggerDef.TableName and PolicyDef.TableName — append those changes as table-level details via a post-processing pass.
         Specifically: after building Added/Removed lists, scan for TriggerDef and PolicyDef entries. For each trigger/policy in Added that references a table in both maps, move it from Added into that table's Changed.Details as "トリガー追加: <name>" / "ポリシー追加: <name>". Same for Removed. If the table itself is not in Changed yet, create an ObjectChange entry for it. If the table is itself new/removed, the trigger/policy stays in the top-level Added/Removed section.

    5. Implement `diffNonTable(a, b core.ObjectDef) []string`:
       - Use the serializer byte-comparison approach: get the serializer for the kind, serialize both, compare bytes
       - If bytes differ: return ["本体変更あり"] for functions/triggers, ["定義変更あり"] for views/matviews, ["設定変更あり"] for sequences/types/domains/enums/policies/fks
       - If bytes same: return nil
