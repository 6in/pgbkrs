```
Trigger:    DROP TRIGGER IF EXISTS name ON schema.tablename CASCADE
```

<task type="auto" tdd="true">
  <name>Task 2: Implement Function and Trigger DDL generators</name>
  <files>internal/ddl/function/generator.go, internal/ddl/function/generator_test.go, internal/ddl/trigger/generator.go, internal/ddl/trigger/generator_test.go</files>
  <behavior>
    - Function Test 1: GenerateDDL returns FunctionDef.Definition unchanged (passthrough)
    - Function Test 2: DROP FUNCTION IF EXISTS schema.name(argtypes) CASCADE (includes arg signature)
    - Function Test 3: DROP with empty ArgTypes produces schema.name() (no args)
    - Trigger Test 1: CREATE TRIGGER name TIMING EVENT1 OR EVENT2 ON schema.tablename FOR EACH ROW EXECUTE FUNCTION schema.functionname()
    - Trigger Test 2: Single event (no OR)
    - Trigger Test 3: DROP TRIGGER IF EXISTS name ON schema.tablename CASCADE
    - Both: Wrong type returns error
  </behavior>
  <action>
1. **Function generator** (`internal/ddl/function/generator.go`):
   - Replace stub. Type-assert to `core.FunctionDef` (value receiver).
   - `GenerateDDL`: Return `fd.Definition` directly as single-element slice. Do NOT reconstruct — pg_get_functiondef() output is already the complete CREATE OR REPLACE FUNCTION statement.
   - `GenerateDrop`: `DROP FUNCTION IF EXISTS schema.name(argtypes) CASCADE`. Use fd.ArgTypes for the argument signature. If ArgTypes is empty, use empty parens: `schema.name()`.

2. **Trigger generator** (`internal/ddl/trigger/generator.go`):
   - Replace stub. Type-assert to `core.TriggerDef` (value receiver).
   - `GenerateDDL`: Assemble `CREATE TRIGGER name\n    timing events ON schema.tablename\n    FOR EACH ROW EXECUTE FUNCTION schema.functionname()`
     - Events joined with ` OR ` (e.g., "INSERT OR UPDATE")
     - Schema for table and function comes from td.Schema (trigger's schema = table's schema = function's schema in standard setups)
   - `GenerateDrop`: `DROP TRIGGER IF EXISTS name ON schema.tablename CASCADE`

**Pitfalls (from research):**
- Function DROP requires argument signature — overloaded functions need argtypes to disambiguate
- Trigger DROP requires ON table_name — trigger names are scoped to their table
- Trigger: Use FOR EACH ROW as default (TriggerDef does not currently store row vs statement granularity; research notes this limitation)
