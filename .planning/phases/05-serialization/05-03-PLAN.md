    1. Keep `DataMeta` struct with proper field tags (not YAML -- this struct is used programmatically, not serialized directly):
       ```go
       type DataMeta struct {
           File     string   // always "data.csv"
           Columns  []string // column names in order
           RowCount int64    // from CommandTag.RowsAffected()
           Checksum string   // "sha256:<hex>"
       }
       ```

    2. Keep `ShouldExportData(td *core.TableDef) bool` returning `td.Partitioning == nil`.

    3. Implement `ExportTableData(ctx context.Context, conn *pgx.Conn, schema, table, filePath string, columns []string) (*DataMeta, error)`:
       - Create file at filePath with os.Create
       - Create sha256.New() hash
       - Create io.MultiWriter(file, hash) for single-pass streaming
       - Execute `COPY "schema"."table" TO STDOUT WITH (FORMAT CSV)` via conn.PgConn().CopyTo(ctx, multiWriter, sql)
       - ALWAYS quote schema and table identifiers in the COPY command to handle mixed-case names safely
       - Extract row count from CommandTag.RowsAffected()
       - Compute checksum as "sha256:" + hex.EncodeToString(hash.Sum(nil))
       - Close file before returning (use defer, but also consider explicit sync for data safety)
       - Return DataMeta with File="data.csv", Columns=columns, RowCount, Checksum

    4. Error handling: if CopyTo fails, attempt to remove the partial file before returning the error.

    5. Update csv_test.go: make the ShouldExportData tests runnable (not skipped). Keep ExportTableData tests with t.Skip("requires live database") for now -- these will be validated in integration testing during Phase 7.

    Imports needed: context, crypto/sha256, encoding/hex, fmt, io, os, github.com/jackc/pgx/v5, github.com/pgbkrs/pgbackup/internal/core.
