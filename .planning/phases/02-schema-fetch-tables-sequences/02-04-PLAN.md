Use the query from RESEARCH.md "Query: Composite Types in a Schema":

```sql
SELECT
    t.oid,
    t.typname AS name,
    a.attname AS field_name,
    format_type(a.atttypid, a.atttypmod) AS field_type
FROM pg_type t
JOIN pg_namespace n ON t.typnamespace = n.oid
JOIN pg_class c ON t.typrelid = c.oid
JOIN pg_attribute a ON a.attrelid = c.oid
WHERE t.typtype = 'c'
  AND c.relkind = 'c'
  AND n.nspname = $1
  AND a.attnum > 0
  AND NOT a.attisdropped
ORDER BY t.typname, a.attnum
```

CRITICAL: The `c.relkind = 'c'` filter is what excludes table row types. Without it, every table in the schema would appear as a composite type. This is PITFALL 1 from RESEARCH.md.

Use the query from RESEARCH.md "Query: Domains in a Schema":

```sql
SELECT
    t.oid,
    t.typname AS name,
    format_type(t.typbasetype, t.typtypmod) AS base_type,
    NOT t.typnotnull AS nullable,
    COALESCE(pg_get_expr(t.typdefaultbin, 0), '') AS default_expr,
    COALESCE(c.conname, '') AS check_name,
    COALESCE(pg_get_constraintdef(c.oid), '') AS check_definition
FROM pg_type t
JOIN pg_namespace n ON t.typnamespace = n.oid
LEFT JOIN pg_constraint c ON c.contypid = t.oid AND c.contype = 'c'
WHERE t.typtype = 'd'
  AND n.nspname = $1
ORDER BY t.typname
```

Map to `core.DomainDef`:
- ObjectHeader: Kind=core.KindDomain, Schema=schema, Name=row.Name
- BaseType from format_type output
- Nullable from NOT typnotnull
- Default from COALESCE(pg_get_expr(...), '')
- CheckName from COALESCE(conname, '')
- CheckDefinition from COALESCE(pg_get_constraintdef(...), '')

Note: `pg_get_constraintdef(c.oid)` returns something like `CHECK ((VALUE > 0))`. The test assertion checks `Contains "VALUE > 0"` (not exact equality) to be resilient to PostgreSQL parenthesization.
